## 0. 结论先行

| # | 裁定 | 依据 | 代价 |
|---|---|---|---|
| A1 | **节点只测量，协同全在后端。** C5 不参与多节点协商，节点之间不直接通信 | 单节点已是完整测量机（`scanner.c` 一条流水线出全部指标 **[已由源码确认]**）；C5 启动后堆约 5 KB、静态 RAM 剩几百字节 **[已由真机实测]**（`CLAUDE.md:107-109`） | 后端必须承担重排、对齐、缺帧处理；断网期间节点无法"自行组队" |
| A2 | **节点身份走传输层，不进帧。** 沿用 `(gateway_id, transport_addr)` 作为节点全局唯一键 | `models.py:195-205` 已把该二元组定为 `UniqueConstraint`，并明文"禁止按显示名全局去重" **[已由源码确认]**；中继管道刻意"无信封"（`relay_pipe.h:1-8`，spec 分歧 B 的裁定 **[已由源码确认]**） | 一块板换接线（USB→中继）就换身份，需另加设备级持久 id 才能合并（见 `device-protocol-v2.md` §1） |
| A3 | **落地顺序：先 B（全复制）→ 再 A（频段分工）→ C（动态调度）后置** | B 模式零固件改动，只动后端聚合与工作台视图；A 需要后端下发分工计划；C 需要 A/B 的数据先站稳 | B 模式的带宽是 A 的 N 倍（§5） |
| A4 | **时间基准：双时间戳。** 帧内 `t_ms`（节点开机毫秒）+ 网关侧接收时戳，二者都存，不互相覆盖 | `t_ms = esp_timer_get_time()/1000`（`scanner.c:332,468,489`）**[已由源码确认]**，是各节点自己的单调里程表，跨节点不可比 **[根据源码推断]** | 跨节点对齐精度受链路抖动限制，量级需实测（§3.4） |
| A5 | **原始帧永远保留，融合只是派生视图。** 提供 MAX / AVG / PER_NODE / LAST 四种语义，用户选，系统不猜 | 现有固件本就"没有全局 max-hold，SPEC 的 MAX 只是显示抽取时每个 bin 取最大"（`PROJECT-REPORT §3.4`）**[已由源码确认]** | 存储成本按节点数线性增长，需要保留策略配合 |
| A6 | **跨节点电平比较默认不可信。** 不同芯片/不同频段/不同增益的读数不得直接同图比较 | 真机已确认"两板不同频段不可跨板比电平" **[已由真机实测]**（S3+C5 双板 USB 接入那轮） | 首版多节点视图要显式打"不可比"标签，比"看起来能比"更难看但更诚实 |

## 1. 多节点只有两个价值维度

单机 8 频道轮扫已经是一张完整的局部频谱图，多节点**不是**"把 N 张图拼更大"。真正的增量只有两类：

| 维度 | 得到什么 | 需要什么 | 归入 |
|---|---|---|---|
| **覆盖** | 单次旋转的瞬时全频段快照（单机是时间交错采样，非同时） | 各节点分频段 + 后端按同一时间栅格合并（A 模式） | 频谱监视 / 频道占用统计 |
| **空间** | 同一时刻同一频点在不同位置的读数 | 各节点同频道 + 位置元数据 + 可比性标签（B 模式） | 干扰定位辅助 / 信号源移动 |

> **A6 的注脚**：覆盖维度对电平精度不敏感（各频段各自定标即可），空间维度则完全依赖可比性。**所以 §2 的两种模式不是同一件事的两面，是两条独立的验收线。**

## 2. 三种工作模式

### 2.1 B：全节点全频道复制（首版）

每个节点扫相同频道表，后端按 (频点, 时间栅格) 聚合。

- **不改固件** **[已由源码确认]**：现有 `CHANNELS`/`SCAN START` 命令与 METRICS/SPECTRUM 帧已经足够，多节点只是"N 条已有链路"。
- 用途：验证数据模型、时间对齐、可视化——这三件事与"分工"无关，B 模式就能全部暴露。
- 代价：带宽 ×N（§5）；同一频段的重复测量对"覆盖"维度零增益。

### 2.2 A：频段分工（次版）

后端把频道表切成 N 份，分别下发；合并后得到"同时刻全频段"。

- 依赖：后端要能按节点能力分配（哪些节点在同一频段、哪些能力 `undeclared` **[已由真机实测]**：能力位缺口已申报过）。
- 关键约束：**单机最多 8 频道** 是协议层的硬上限（`ENABLE` 位图宽度），分工不是"每节点 8 频道、总数不限"，而是"总数仍受每节点 8 限制，N 个节点合计 ≤ 8N"**[已由源码确认]**。
- 失败形态：某节点离线 → 该频段出现**盲区**，必须在图上显式画出盲区时段，而不是静默用邻节点的值补。

### 2.3 C：混合动态调度（后置）

按观测到的占用/干扰，运行时重排各节点频道表。

- **本版不做**，理由：调度质量取决于 B/A 稳定采集到的数据可信度；且重排会让"同一频点跨时间可比"这条前提失效（换节点测同频点 = 换了一次标定），需要先把 A6 的可比性标签解决。
- 记录一个必须提前留的口子：调度权归后端，节点只接受"新频道表"这种已有命令（`CHANNELS` + `ENABLE`），**不需要**新协议 **[已由源码推断]**。

## 3. 时间对齐：多节点最容易做错的地方

### 3.1 第一原则：到达时间不是采样时间

链路有队列、有节流、有中继转发。`frames.h` 的 `t_ms` 是节点自己的开机毫秒 **[已由源码确认]**；网关看到帧的时刻与它真正被采出的时刻差着不确定的量。**两者都要存**，任何"按到达顺序当时间轴"的实现都是错的。

### 3.2 第二原则：每节点独立时间映射

- `seq_metrics` 与 `seq_spectrum` 是两条独立计数，且 METRICS 与 LEVELS 共用 `seq_metrics`（`scanner.c:60,331,467`）**[已由源码确认]** → **序号不能跨帧类型对齐，只能在同类帧内检测缺口。**
- `t_ms` 是 `uint32_t` 毫秒，约 **49.7 天回绕** **[根据源码推断]** → 后端必须检测回绕，不能假设单调递增于整个会话生命周期。
- 做法：每节点维护 `(uptime_ms ↔ gateway_wallclock)` 线性映射，用往返时延法做一次粗标定 + 周期重标；原始 `t_ms` 永不改写。

### 3.3 第三原则：允许误差，但必须标注质量

跨节点瀑布图的对齐误差要作为**数据属性**呈现（例如每行带 `sync_quality` 标记），而不是藏在一个全局"已同步"徽标里。

### 3.4 精度量级（待验）

M1 那轮实测 `INFO` 三次往返 **9 / 12 / 43 ms** **[已由真机实测]**（见 `topology-and-access-methods.md` §0 方式③）→ 往返法给的对齐误差下界约 **±20 ms** 量级。

- 对"覆盖"维度：够用（一次 8 频道旋转 ~32 ms，误差与旋转周期同阶 **[根据源码推断]**）。
- 对"空间"维度的辅助定位：**不够**（见 §8 D3）。

## 4. 融合语义

| 语义 | 定义 | 用途 | 陷阱 |
|---|---|---|---|
| `PER_NODE` | 不融合，每节点一条迹线 | 节点对比、判定谁看到的更强 | 视图纵向空间随节点数增长 |
| `MAX` | 逐 (频点, bin) 取最大 | 全景监视"这里有没有信号" | 掩盖节点间差异，不能用于定位 |
| `AVG` | 取均值（需可比性标签） | 场地基线、噪声底趋势 | A6 未满足时是**错误**的数字 |
| `LAST` | 取最新一条 | 实时跟随、告警输入 | 依赖到达顺序，见 §3.1 |

融合结果与原始帧同库不同表，派生视图可重算、可删除。

## 5. 传输与规模

两种接入并存（详见 `topology-and-access-methods.md`）：

| 接入 | 现状 | 单节点带宽 | 上限 |
|---|---|---|---|
| ① USB × N → 接入机 | **已真机验证**（双板并跑 C5 37 / S3 52 KB/s、0 CRC **[已由真机实测]**） | 实测 37–52 KB/s | 受接入机 USB 端口数与 `serve.mjs` 单主端口约束 |
| ③ Wi-Fi 中继（S3 主控 + C5 扫描头） | **M2 软件侧完成、真机未执行**（并行会话在做，本文不重复其结论） | 未实测 | **本架构最大的未验量**，见 §6 前置条件 |

**理论带宽账**（默认配置：`FULL`、8 通道、~4.0 ms/hop、`SPEC` 每 4 hop、尺寸取自 `frames.h:118-122` **[已由源码确认]**）：

| 帧 | 字节/帧 | 频率 | 小计 |
|---|---|---|---|
| METRICS | 6 + 34 + 8×26 + 4 = **252** | ~250/s | **~63.0 KB/s** |
| SPECTRUM | 6 + 16 + 256 + 4 = **282** | ~62.5/s | **~17.6 KB/s** |
| TELEMETRY | 6 + 59 + 4 = **69** | 4/s | ~0.3 KB/s |
| 合计 | | | **~80.9 KB/s** |

实测低于上界（节流、`METRICS` 压缩档、链路队列保护：频谱只留 1/4 队列 **[已由源码确认]** `scanner.c:258-259`）。**[需要实机验证]** 8 节点（~0.65 MB/s）在 Pi 上经中继链路的余量。

规模承诺：**按 8 节点设计**（与既有 `MAX_GATEWAYS=8` 同量级），不对 32+ 节点做任何承诺。本地 4 节点 300 s 压测 1134 帧/s、RSS 70–80 MB **[已由真机实测]**（S9-4）是当前的唯一容量证据。

## 6. 呈现：四视图与其边界

| 视图 | 内容 | 依赖 |
|---|---|---|
| V1 全场频谱全景 | 多节点合并迹线（可选四种融合语义） | §4 + A 模式 |
| V2 多节点瀑布 | 每节点一条瀑布带，共享时间栅格 | §3 |
| V3 场地分布 | 节点位置 + 电平热区 | 位置元数据 + A6 标签 |
| V4 节点对比 | 同频点跨节点并排 | `PER_NODE` |

**边界（硬约束）**：多节点 UI 只落在 `rftrack/frontend/workbench/`，**不改 `web/`**。理由：rf-track 线自 S0 起对 `web/`、`firmware/`、`serve.mjs` 一行未碰是既有纪律 **[已由源码确认]**（`git diff --stat HEAD -- web firmware serve.mjs` 的口径），且分支隔离裁定是"rf-track 永不合入 main"。

**M2 是 V1/V2 的前置，不是后置**：中继数据面未经真机射频并发验证前，任何"多节点频谱"都只能在 USB 接入机上演示。

## 7. 三个高级方向（都排在 MVP 之后）

| 方向 | 价值 | 现在的拦路石 |
|---|---|---|
| 干扰源辅助定位 | 从"发现异常"到"指出方向区域" | §3.4 精度不够 + 需 ≥3 节点已知位置 + 可比性 |
| 信号源追踪（运动） | 视频丢失时的飞行轨迹推测 | 同上 + 需要跨时间的同一次测量身份（**不能只靠频率+RSSI 认定同一物理发射源**，多机同频道是常态） |
| 比赛现场频谱管理 | 频道分配建议、冲突预警 | A 模式覆盖 + 占用统计口径（现有 `AVG` 时间平均语义要先讲清） |

## 8. 待拍板决策

> 每条都是真实分歧点，推荐值已给出，但**需要你确认**。

**D1 节点身份：传输层（推荐）还是帧内 tag？**
推荐传输层（A2）。帧内加 node id 要同时改固件帧、`web/src/proto/frames.ts`、`frame_parser.py`、中继的无信封设计四处，且中继透传会立刻失真。代价：换接线的同一块板会被当成两个节点，靠 `device-protocol-v2.md` 的设备级持久 id 补偿。

**D2 首版做 B（全复制）还是 A（分工）？—— ✅ 已拍板：B（2026-11-02 用户确认）**
推荐 B（A3）。B 零固件改动、能同时暴露对齐/融合/视图三个风险；A 的"盲区必须显式化"要求后端先有可信的时间栅格。**Trade-off（已接受）**：B 烧带宽（§5 的 ×N），且对"覆盖"维度零贡献——"同时刻全频段"顺延到 A 模式（§10 的第 8–10 周）。

**D3 跨节点对齐精度目标定多少？**
推荐先承诺 **±20 ms**（往返法可达 **[已由真机实测]** 量级），把"辅助定位"从本期目标里删掉。**代价**：真要定位就得引入 SNTP/硬件触发，那是另一条固件线。

**D4 跨节点电平比较：默认禁止还是默认允许？**
推荐**默认禁止**，图上打"不可比"标签（A6），等 dBm 校准链路做完再放开。**代价**：首版多节点视图看起来"信息更少"，用户可能觉得退化。

**D5 规模上限：8 节点写进架构还是留弹性？**
推荐写死 8（与 `MAX_GATEWAYS=8` 一致），并明确"超出即不支持，不承诺性能"。**代价**：将来真要 32 节点时，这行字要重写。

## 9. 非目标（本期明确不做）

- 不做 IQ 级多节点融合，不做相控阵/分布式接收。
- 不做节点间直接通信（Mesh/自组网）。
- 不做云端部署（既有边界：每场地一套实例 + 局域网只读汇聚）。
- 不改 v1 线协议的任何现有字段（见 `device-protocol-v2.md` §0）。
- 不在 C5 上加任何新的动态内存分配。
